# Frontend-Ready API Contract: pydantic v2, one status enum, session list/get/delete, explicit list envelope, one error shape, UTC at the edge, one length limit, documented WS events, committed OpenAPI snapshot

> Read "Gates and open decisions" in section 1 before starting any work package.
> WP-8 is GATED on human sign-off. WP-1 to WP-7 are not F1/F2-gated.

## 1. Requirement
> The API contract MUST be frontend-ready: (1) pydantic v2 idioms only (ConfigDict(from_attributes=True), json_schema_extra, model_dump; no class Config, orm_mode, schema_extra or .dict()) and no deprecation warnings from touched files; (2) message status MUST be one enum shared by schemas and service, using the REQ-0003 vocabulary queued/running/completed/error/cancelled unchanged; (3) session list, get and delete endpoints MUST exist under /api/v1/sessions with uuid ids and 404 on unknown ids, any SessionStore widening MUST be justified per PAT-ARCH-001; (4) the list-messages response shape MUST be explicit and in OpenAPI (envelope or bare list decided by architect), and MessageListResp MUST be used or removed; (5) all REST and intel error bodies MUST share one shape, and the unreachable 429 queue-full path MUST be removed or made reachable; (6) API datetimes MUST serialize as timezone-aware UTC while storage stays naive UTC per ADR-0003; (7) REST and WS MUST enforce one shared user-message length limit via app/services/messages.py, reconciling MessageCreateReq 16384 with MAX_INPUT_TOKENS*4 4096; (8) the WS event contract MUST be documented without token streaming; (9) a committed openapi.json MUST exist with a test that fails on drift, a documented one-command regenerate step, and no new dependency. Streaming (REQ-0007), auth/CORS (REQ-0009), persistence (REQ-0005), prompt pipeline (REQ-0006), tools (REQ-0008), campaign domain (REQ-0015) and repo hygiene (REQ-0012) MUST NOT change; accepted ADRs and patterns MUST NOT change without human sign-off. (REQ-0010)

#### Defaults chosen by the architect (carry as written; do not deviate without a human decision)
| Id | Default |
|---|---|
| D-1 | 422 validation `detail` stays FastAPI's list `[{loc, msg, type}]`. No custom `RequestValidationError` handler (so `app/factory.py` is not touched). |
| D-2 | No machine-readable error `code` field. Clients switch on HTTP status and show `detail`. |
| D-3 | `snapshot_at` becomes a UTC datetime string (was an epoch float). |
| D-4 | Session delete is a hard delete, cascades messages (messages first, in one transaction), is allowed while a reply is in flight, and returns 204. The worker logs the `KeyError` for in-flight jobs of a deleted session. |

| D-6 | Session list is newest first. |
| D-7 | Enqueue failure marks the message `error` (`meta.error = "enqueue failed"`); REST returns 503; resending the same `client_message_id` returns the errored message. |
| D-8 | WS error events keep the key `message` (not `detail`). |
| D-9 | `SessionCreateResp.capabilities.streaming` stays `true` (REQ-0007 owns it). |

#### Assumptions where the inputs were ambiguous (flagged for review)
- **A-1** REQ item 1 lists `ConfigDict(from_attributes=True)` as an example idiom. ADR-0005 item 1 decides `from_attributes` is NOT added, because the store returns dicts. This spec follows the ADR: `ConfigDict(json_schema_extra=...)` only.
- **A-2** The idempotent replay of `POST .../messages` (HTTP 200) now has the body of `MessageAcceptedResp`: `{message_id, status, queue_position: null}` (before: `{message_id, status}`).
- **A-3** `GET .../messages/{id}/status` now always emits all five `MessageStatusResp` keys (`queue_position` / `estimated_wait_seconds` are `null` when unknown; before they were omitted).
- **A-4** `GET /api/v1/sessions/{id}` reads `created_at` from `list_sessions()` (ADR-0005 item 3); there is no `get_session_info` method.
- **A-5** After an enqueue failure the helper returns the re-read stored message (status `error`), so the WS `entry` event for that user message already shows `"status": "error"`.
- **A-6** `docs/api/` does not exist yet; WP-7 creates it (needs `mkdir -p`; the implementer has a shell, the spec author did not).
- **A-7** `ruff`/`black` are run as `./venv-dnd-server/bin/python -m ruff check <files>` and `-m black --check <files>` if installed (SPEC-0007 used them); if not installed, skip and say so in the report.

### Verified facts (checked against the tree on 2026-10-11; line numbers may drift by a few lines)
- Next spec number requested by the coordinator: SPEC-0010 (existing: SPEC-0001..SPEC-0007).
- `app/schemas/v1.py`: nine models use `class Config` + `schema_extra` (`SessionCreateResp`, `MessageCreateReq`, `MessageResp`, `MessageStatusResp`, `MessageListResp`, `ToolListResp`, `ToolInvokeResp`, `IntelligenceStatusResp`, `SessionSnapshotResp`); `MessageResp` also has `orm_mode = True`; `constr` and `ContentStr` are imported/defined but unused; status descriptions and examples say `in_progress`/`done`; `MessageCreateReq.content` allows 16384; `snapshot_at: float`.
- `app/api/v1/session.py`: has `MAX_INPUT_TOKENS = 1024`, `MAX_QUEUE_RETRY_AFTER = 5`, a duplicated `router = APIRouter(...)`, the 400 length check, `payload.dict()`, a 429 `JSONResponse` branch, a bare-list `list_messages`, and no `response_model` on `post_message` / `get_message_status`. Only `POST /api/v1/sessions` exists for sessions, and it has no token dependency (stays so; REQ-0009).
- `app/api/v1/intelligence.py`: `_tool_error` returns `{text, meta, error, detail?}`; `ToolInvokeResp` has `error`.
- `app/api/v1/ws.py`: `TERMINAL_STATUSES = {"completed","error","cancelled"}`; sends raw store dicts for `snapshot` and `entry`; no length limit; error text `"Inference queue full; try again later"`.
- `app/services/messages.py`: `submit_user_message` returns `(message, created, queued)`; `build_snapshot` returns `snapshot_at: time.time()`.
- `app/services/repos.py`: `_now()` uses `datetime.utcnow()`; `sessions(id, created_at)` and `messages(... session_id REFERENCES sessions(id))` with no `ON DELETE CASCADE` and `PRAGMA foreign_keys = ON`; the store raises `KeyError` for unknown ids.
- `app/type_defs.py`: `SessionStore` Protocol has six methods, pinned by `tests/test_single_session_model.py::test_session_store_protocol_unchanged`.
- `app/services/inference_service.py` writes `queued/running/completed/error/cancelled` as string literals; the queue is an unbounded `Queue()`; `enqueue` returns `False` only from its broad `except`.
- Test helpers: `tests/conftest.py` fixtures `stub_client`, `stub_svc`, `session_store`, `client`, `app`; `tests/session_helpers.py` has `AUTH`, `FakeInference(accept=True)`, `wait_idle`, `make_stub_service`. `tests/test_backlog_schema.py` reads `.github/BACKLOG.json` and `docs/requirements/LOG.md`; it must still pass and nothing here edits those files.
- Out of scope files that must stay untouched: `app/config.py` (its `.dict()` at ~line 174), `app/factory.py` (`on_event`), `settings.json`.
