# Pattern Index

| ID | Category | Name | Status | Summary |
|---|---|---|---|---|
| PAT-ARCH-001 | architecture | One session store API; transports are thin adapters | accepted | uuid session ids everywhere; the `SessionStore` Protocol (via `get_session_store()`) is the only session-state API; REST/WS/`/intel` are thin adapters; replies are written only by the worker; no `hasattr` fallbacks or private stores. |
| PAT-ARCH-002 | architecture | Local persistence with stdlib `sqlite3` behind a Protocol | accepted | One `check_same_thread=False` connection plus one lock per store; reads return fresh dicts, every write is an explicit method in one transaction; unknown ids raise `KeyError`; datetimes as ISO TEXT, dicts as JSON TEXT; schema via `CREATE IF NOT EXISTS` + `user_version`; path from `database.url`; tests use `:memory:`. |
| PAT-ARCH-003 | architecture | Prompt pipeline: pure builders over store dicts, assembled by the worker at run time | accepted | Builders take store message dicts and plain settings values, do no I/O and no ORM access, and return `[system, ≤max_turns completed prior (oldest first, truncated), current user]`; voice config is loaded once with fallback to `{}` and a `get_logger` warning; the worker builds the prompt at run time from `list_messages` and calls `OllamaClient.chat`; `generate(prompt)` wraps `chat`; transports and Protocols are unchanged; no prompt text in logs. |
| PAT-ARCH-004 | architecture | Slash-command tools run in the inference worker; results are assistant replies | accepted | Tools are `NAME` + `run(args: str, context: dict) -> str or {"text","meta"}` and raise `ToolError` on bad input; the worker dispatches `/name args` (via `detect_tool`) and writes the result as a `role='assistant'` reply with `meta.tool`/`meta.reply_to`; server context keys cannot be overridden by clients; `invoke` raises typed errors (HTTP 404/400/502/500) and runs tools outside the registry lock; Ollama calls share one `_ollama_lock`; the `clear` tool is deleted and `/clear` is an unknown tool (ADR-0004). |
| PAT-ARCH-005 | architecture | HTTP/WS API contract: FastAPI defaults, explicit models, UTC at the edge, checked-in OpenAPI | accepted | Errors are `HTTPException` -> `{"detail": str}` (422 keeps FastAPI's list); every route has a `response_model` and collections are `{"<plural>": [...]}`; shared vocabularies are `StrEnum`s in `app/type_defs.py`; datetimes stay naive-UTC in storage and are emitted as aware UTC via `UtcDatetime` (WS goes through the same models); input limits are one constant enforced in the shared helper; pydantic v2 idioms only; `docs/api/openapi.json` + drift test + `docs/api/websocket.md` (ADR-0005). |
| PAT-ARCH-006 | architecture | Curated reference data: file-canonical in git, normalized at ingest, loaded once, served read-only | accepted | One normalized JSON per dataset under `app/reference/` (git is the version history); raw consultant files are provenance only; normalize at ingest (snake_case, stable `id` slug, edition and publisher kept separate, third-party flag); pydantic model, loaded once while services are built, fail-soft at runtime and fail-hard in a CI test; read-only GET routes with PAT-ARCH-005 envelopes; tools read the in-memory catalog; user records reference entries by `id` TEXT with no FK; shared loader only once a second dataset exists (ADR-0006). |
| PAT-ARCH-007 | architecture | Bulk upstream reference sources: sync to gitignored scratch, allowlist and project at ingest | accepted | Upstream APIs (e.g. open5e) are build-time inputs only: an on-demand `scripts/sync_<source>.py` writes raw snapshots and a manifest to a gitignored scratch dir; ingest only datasets with a named consumer; allowlist upstream documents (SRD by default), project to the needed fields, normalize per PAT-ARCH-006, keep upstream key as `source_key`; repo-owned ids with the curated overlay winning; files stay under 2 MB / 2,000 entries (CI-tested), else that dataset falls back to a derived read-only SQLite under the same `reference` key; generated `ATTRIBUTION.md` (ADR-0007). |
| PAT-ARCH-008 | architecture | Schema migrations: ordered `user_version` ladder in the store constructor | accepted | Base schema frozen at v1; additive steps (new nullable column or new table) in one append-only `(version, table, column or None, ddl)` list applied on open, each in an explicit transaction with a `table_info`/`sqlite_master` idempotency guard and a `user_version` bump; never downgrade; old-file-DB test per step; non-additive changes need an ADR (ADR-0008). |
| PAT-ARCH-009 | architecture | Reference-grounded LLM tools: deterministic selection, bounded excerpt budget, flagged training fallback | accepted | Tools read only the in-memory catalog; a pure stdlib selector (name-weighted, threshold, edition tie-break) packs whole entries in rank order within one chars setting, never truncating; the top entry over budget, no match or an empty catalog means training mode; `meta.source` is `<dataset>` or `training` with an always-present ids list; the training reply gets a fixed disclaimer; one-shot pure builder with no narrator voice; counts-only logs; no shared code until a second tool uses the keyword selector (ADR-0009, ADR-0012). |
| PAT-ARCH-010 | architecture | Non-destructive message corrections: `canon` column, in-place revisions, canon-only history | accepted | `messages.canon` (ladder v4, nullable, NULL = canon) exposed as `canon: bool`; content changes append `{content, replaced_at, reason}` to reserved `meta.revisions` (original first), nothing deleted; one store write method for edit/canon/regenerate; regenerate re-enqueues the user message and the worker revises its one reply in place; every history consumer filters on `canon` (ADR-0011). |
| PAT-ARCH-011 | architecture | Structured reference lookup tools: deterministic name match and render, no LLM on a hit | accepted | Tools that show one named catalog entry read the in-memory catalog, match casefolded exact-then-substring names (several distinct names = `ToolError` listing up to 5, 5.5e preferred unless an edition token is given), render the entry with a pure, string-tested function, and never call the LLM on a hit; a miss is a `ToolError` or (after `difflib` typo suggestions) one PAT-ARCH-009 flagged training call; counts-only logs; share code at the third caller (ADR-0012). |
| PAT-CODE-001 | code | Centralized logging via app.services.logger | accepted | Use `get_logger(__name__)` from `app/services/logger.py` everywhere; no stdlib `logging.getLogger` or `print()` for app logging. |

## Mechanically enforced (do not open the pattern to re-check these rules)

`tests/test_patterns.py` fails with a one-line message when these are broken. Open the
pattern file only when designing something new in that area.
